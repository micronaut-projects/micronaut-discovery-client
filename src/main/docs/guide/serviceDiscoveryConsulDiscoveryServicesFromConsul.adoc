= Discovery Services from Consul

To discovery other services you could manually interact with the link:{micronautapi}discovery/DiscoveryClient[DiscoveryClient], however typically instead you use the https://docs.micronaut.io/latest/guide/index.html#clientAnnotation[Client Annotation] to declare how an HTTP client maps to a service.

For example the configuration in the previous section declared a value for `micronaut.application.name` of `hello-world`. This is the value that will be used as the service ID when registering with Consul.

== Filtering Discovered Instances

By default service instances are looked up with Consul's `/v1/health/service/{service}` endpoint without any tag or filter. The following `consul.client.discovery` settings narrow down and tune that query:

.Filtering Discovered Instances
[configuration]
----
consul:
  client:
    discovery:
      passing: true
      consistency-mode: stale
      query-tags:
        inventory:
          - primary
          - v2
      default-query-tags:
        - production
      filters:
        inventory: 'Service.Meta.version == "2"'
      default-filter: '"canary" not in Service.Tags'
      datacenters:
        inventory: dc2
----

[cols="1,3"]
|===
|Property |Description

|`passing`
|Only return instances whose health checks are all passing (default `false`).

|`query-tags`
|A map of service ID to the tags to query with. Only instances that carry every tag are returned. Each tag is sent as a repeated `tag` query parameter.

|`default-query-tags`
|The tags to query with for services that have no entry in `query-tags`.

|`tags`
|Deprecated: a map of service ID to a single tag. Use `query-tags` instead. It is still honored when a service has no entry in `query-tags`.

|`filters`
|A map of service ID to a https://developer.hashicorp.com/consul/api-docs/features/filtering[Consul filter expression] sent as the `filter` query parameter.

|`default-filter`
|The filter expression to use for services that have no entry in `filters`.

|`consistency-mode`
|The https://developer.hashicorp.com/consul/api-docs/features/consistency[consistency mode] of the query: `default`, `consistent` (sends the `consistent` flag) or `stale` (sends the `stale` flag, allowing any Consul server to answer).

|`datacenters`
|A map of service ID to the data center to query.

|`schemes`
|A map of service ID to the scheme (`http` or `https`) used to call the instances (default `http`).
|===

These settings correspond to the `server-list-query-tags`, `default-query-tag`, `query-passing` and `consistency-mode` settings of Spring Cloud Consul.

The same options are available programmatically through the `findHealthyServices(service, passing, tags, dc, filter, consistencyMode)` method of api:discovery.consul.client.v1.ConsulClient[].
