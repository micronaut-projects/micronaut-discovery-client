https://github.com/spring-cloud/spring-cloud-config[Spring Cloud Config Server] Spring Cloud Config provides server-side and client-side support for externalized configuration in a distributed system. With the Config Server, you have a central place to manage external properties for applications across all environments.

A Micronaut application can be a Spring Cloud Config client to consume Spring Cloud Config Server configurations.

The legacy bootstrap `ConfigurationClient` approach is deprecated. Prefer `micronaut.config.import` for new applications and migrations.

== Setup

The quickest way to start a Spring Cloud Config Server is to use to use https://github.com/spring-cloud/spring-cloud-config#quick-start[Spring Boot's Quick Start].

== Loading configurations from config server

The preferred process to consume configurations in a Micronaut application from a Spring Cloud Config Server is to use an explicit import URI:

.Importing configuration from Spring Cloud Config Server
[configuration]
----
micronaut:
  config:
    import: "springcloud://configserver:9000/hello-world/default"
----

To target multiple profiles or a Git label:

.Importing configuration with multiple profiles and label
[configuration]
----
micronaut:
  config:
    import: "springcloud://configserver:9000/hello-world/first,second?label=main"
----

For secured servers, prefer credentials in the URI authority:

.Importing from a secured Spring Cloud Config Server
[configuration]
----
micronaut:
  config:
    import: "springcloud://user:password@configserver:9000/hello-world/default"
----

Query-parameter credentials are also supported during migration, but URI user-info is preferred:

.Importing from a secured Spring Cloud Config Server with query parameters
[configuration]
----
micronaut:
  config:
    import: "springcloud://configserver:9000/hello-world/default?username=user&password=secret"
----

Treat import URIs with embedded credentials as sensitive values and store them accordingly.

=== Spring Cloud Config import URI reference

[cols="1,1,3"]
|===
|ConnectionString part |Example |Meaning

|Scheme
|`springcloud://`
|Selects the Spring Cloud Config importer.

|User info
|`springcloud://user:password@configserver:9000/...`
|Optional Basic-auth credentials. `username` and `password` query parameters are also supported, but user-info is preferred.

|Host and port
|`configserver:9000`
|Spring Cloud Config Server host and port.

|Path
|`/hello-world/default`
|Required. The first path segment is the application name and the second is the profile list. Multiple profiles may be comma-separated.

|Query string
|`?label=main&fail-fast=false`
|Optional importer settings.
|===

[cols="1,1,3"]
|===
|Option |Example |Description

|`label`
|`?label=main`
|Optional Git label or branch requested from the Config Server.

|`fail-fast`
|`?fail-fast=false`
|Whether failures should abort startup immediately.

|`username`
|`?username=user`
|Optional Basic-auth username. Prefer URI user-info instead.

|`password`
|`?password=secret`
|Optional Basic-auth password. Prefer URI user-info instead.

|`retry-attempts`
|`?retry-attempts=3`
|Number of config import retry attempts handled by Micronaut's retryable importer support.

|`retry-count`
|`?retry-count=3`
|Alias for `retry-attempts`.

|`retry-delay`
|`?retry-delay=1s`
|Delay between import retries.

|`retry-max-delay`
|`?retry-max-delay=30s`
|Maximum overall retry delay.

|`retry-multiplier`
|`?retry-multiplier=2.0`
|Multiplier applied between retry delays.

|`retry-jitter`
|`?retry-jitter=0.2`
|Retry jitter factor from `0.0` to `1.0`.

|`read-timeout`
|`?read-timeout=5s`
|Read timeout for remote calls.

|`connect-timeout`
|`?connect-timeout=5s`
|Connection timeout for remote calls.
|===

The legacy bootstrap/client configuration is still available during migration. A complete example can be seen below:

.Registering your application as a Spring Cloud Config client
[configuration]
----
micronaut:
  application:
    name: hello-world
  config-client:
    enabled: true
spring:
  cloud:
    config:
      enabled: true
      uri: "http://configserver:9000"
      name: filename1,filename2

----

The field name is optional in the legacy configuration. With `micronaut.config.import`, the application name and profiles are explicit in the URI path.
